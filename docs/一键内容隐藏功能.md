# 一键内容隐藏功能(对外闭站开关)

更新日期:2026-09-08(v3:双通道状态源,修复国内直连访客锁不到的问题)

## 功能定义

在管理后台「🔒 站点开关」页点击**一键隐藏**,访客打开网站只显示首页的星空 3D 动画和每日一句:

- 导航、关于、博客、项目、友链等入口全部消失(首页 header/main/footer 整体隐藏);
- 其余页面没有入口,直接输入 URL 也会被跳回首页;
- **站长不受影响**:登录过管理后台的浏览器会在 `localStorage` 写入站长标记(`cms_owner_at`),守卫脚本据此豁免——站长仍可正常浏览全站、写文章、开发功能;退出登录可切回访客视角检查效果;
- 点击**恢复显示**后一切复原。

**生效时间(由双通道决定,见下)**:任一通道报隐藏即锁——能连上 workers.dev 的访客(有代理)**立即**;国内直连访客靠仓库开关文件,**等 Actions 构建后约 2-3 分钟**(若 Fastly 边缘缓存拖延,最迟约 10 分钟)。注意:访客首屏仍可能有 1 秒级的短暂闪现(客户端软开关的物理极限),重复访问靠缓存秒锁。

## 为什么需要双通道(v3 修复的问题)

v1 只查 workers.dev 的 KV 开关。实测发现:**workers.dev 在国内被墙,直连访客的守卫脚本查状态必然失败**,脚本按「查不到就不锁」处理(防止误伤),结果这些访客完全不受锁影响——这不是浏览器缓存,是状态服务在他们的网络里不可达。

修复:状态源从一条变两条,访客浏览器两条都试:

1. **快速通道(有代理的访客)**:`https://yhl-blog-cms.yuhl.workers.dev/api/site-mode`,读 KV,点开关即时变化;
2. **可靠通道(国内直连访客)**:同源 `/site-mode.json`(即仓库 `public/site-mode.json`,随站点一起从 GitHub Pages 下发)。访客能打开网站就一定能读到它;点开关时后台把它 commit 进仓库,走正常构建(约 2-3 分钟)。

**取值规则(2026-09-09 起「先答先锁」)**:任一通道报「隐藏」→ 立即上锁,不等另一条(workers.dev 被墙时不是快速失败而是挂起几十秒,曾导致微信内置浏览器先看几分钟全文才锁,故 API 探测 3 秒不回话即视为不可达);「恢复」需有通道明确报开放:API 报开放,或 API 不可达且文件报开放;两条都不可达(彻底断网)→ 维持缓存状态。

## 架构

```
管理后台(React 岛屿)
  │ ① POST /api/site-mode { hidden }       (X-Session-Token 鉴权,写 KV,即时)
  │ ② PUT  /api/file/public/site-mode.json (同一后台会话,commit 进仓库,走构建)
  ▼
Cloudflare Worker ──KV(key=site_mode)──▶ GET /api/site-mode → { hidden }   通道①
GitHub 仓库 master ──Actions 构建──▶ GitHub Pages /site-mode.json           通道②
  └────── 两者都被 BaseLayout 内联守卫脚本读取(API 优先,文件兜底)◀── 访客浏览器
```

### 各文件职责

| 文件 | 职责 |
| --- | --- |

| `worker/src/paths.ts` | 白名单精确放行 `public/site-mode.json` 这一个文件 |
| `public/site-mode.json` | 通道②的仓库开关文件(`{"hidden":false}`),后台切换时 commit |
| `src/data/site.ts` | `WORKER_URL` 常量(AdminApp 与守卫脚本共用) |
| `src/layouts/BaseLayout.astro` | 内联守卫脚本(双通道探测)+ `html.site-locked` 隐藏 CSS |
| `src/pages/[lang]/index.astro` | `_fade2d` 在锁站时保留每日一句不淡出 |
| `src/components/admin/AdminApp.tsx` | 「站点开关」页;登录写 `cms_owner_at`,退出清除;切换时双通道同写 |

### 守卫脚本行为细节(BaseLayout)

1. 开发模式(`import.meta.env.DEV`)直接跳过,本地开发完全不受影响;
2. `/admin` 路径永远跳过——这是锁站时的恢复入口;
3. `sessionStorage.site_lock_cache` 缓存本会话已确认的状态:同会话再次导航**同步**生效,不闪现内容;微信等内置浏览器会重置 sessionStorage,故另存 5 分钟内的 localStorage 记忆(`site_lock_last/site_lock_ts`)兜底——重进链接也能秒锁;
   - 已知无解:微信对老分享链接可能自带快照/预取缓存,那层缓存在微信侧,客户端无法主动清除,只能等其自然过期;
4. 每次页面加载双通道探测(文件同源最快,先答先锁;API 3 秒超时判不可达),结果写回两级缓存;已锁的访客若断网,维持锁定(不因断网自动解锁);
5. 锁站逻辑:非首页 `location.replace('/{lang}/')` 跳回首页;首页加 `html.site-locked` 类隐藏 header/main/footer,并保证每日一句可见(主页脚本已淡出时按 `/quotes.json` 当日规则重建);
6. 站长豁免:仅读本机 `localStorage.cms_owner_at`(由后台登录写入、退出清除),不是鉴权——写接口仍要过 Worker 会话;
7. Service Worker 对 `/site-mode.json` 不做任何缓存,永远直连网络。

## 恢复途径(锁站时怎么救回来)

- 站长浏览器本来就豁免,正常用;换新设备时访问 `https://alidadei.github.io/zh/admin/`(守卫对 admin 无条件放行)→ 登录 → 「站点开关」→ 恢复显示;
- 直接调 `POST /api/site-mode`(带有效会话)+ commit `public/site-mode.json` 等效;
- 极端情况可在 Cloudflare 控制台删掉 KV 里 `SESSIONS` 命名空间的 `site_mode` 键,并把仓库里 `public/site-mode.json` 改回 `{"hidden":false}`。

## 已知边界

- 这是**访客视角的软开关**(与《网站防复制与安全边界.md》结论一致):禁用 JavaScript、直接抓 HTML/RSS/图片都能绕过;RSS 与 sitemap 在锁站期间仍可被拉取(静态构建无法动态摘除);
- 访客若连 GitHub Pages 都打不开(彻底断网),Service Worker 会回退到旧缓存 HTML——旧 HTML 里没有守卫脚本,这种离线场景无解,但不影响在线访客;
- 通道②依赖构建:点隐藏到国内访客生效之间有约 2-3 分钟窗口(有代理的访客无此窗口)。

## 上线与回滚

- Worker 先行部署:`cd worker && npx wrangler deploy`(新增接口与白名单对旧版前端无影响);
- 前端随正常构建发布(GitHub Actions),守卫脚本进每个页面;
- 回滚:前端回滚即失去守卫脚本;Worker 接口为纯新增,无需回滚。
